RS_MAN · Phase 1 of 6

RS3 XP Planner Blueprint

Historical XP gains and a planner toward level 99, 120 and 200m in every RuneScape 3 skill, built on the RuneScape Platform API that launched on 4 November 2026.

● Phase 1 complete · awaiting your review

What the new API gives us

Primary source

Index Lite (Hiscores)

index_lite.json?player=NAME returns XP, level and rank for Overall plus 29 skills. Values update a few seconds after the player logs out or hops worlds. Unranked skills still return XP.

Gap

No XP history endpoint

The API has no historical XP endpoint. RuneMetrics xp-monthly retires on 10 Nov 2026 with no replacement. All history after that date has to come from snapshots we take ourselves.

Supporting

Player Events

Returns the last 20 Adventurer's Log events, including level-ups and every 2M XP milestone, behind a 10-minute cache. Members only. Useful for timeline markers, but too sparse to rebuild history from.

Constraint

Server-side only

Responses send no CORS headers, so a browser page can't call Jagex directly. Jagex asks for an identifying User-Agent and caching on our side. No numeric rate limits are published, so we budget conservatively.

Architecture

A small local service polls Hiscores on a schedule and stores snapshots, then derives gains and plans from them. RuneMetrics is used once, before 10 Nov, to seed the past 12 months.

Data model

Display names can change and the API has no stable character ID yet, so each player row stores a normalized key (lowercase, spaces and underscores treated the same) and can be re-linked after a rename.

players

  • id · display_name · name_key
  • added_at · last_checked_at
  • status (ok / not_found / renamed)

snapshots

  • id · player_id · taken_at
  • total_xp · total_level
  • one row per changed poll

snapshot_skills

  • snapshot_id · skill_id (1–29)
  • xp · level · rank
  • -1 kept as "no data"

monthly_rollups

  • player_id · skill_id · month
  • xp_gain · rank
  • source: runemetrics | snapshots

events

  • player_id · date · type
  • text · details
  • unique on (player, date, type, text)

Planner math

Hiscores report each skill's level only up to its current cap (99, 110 or 120, depending on the skill). The planner computes virtual levels from XP, so the 120 target applies to every skill. Invention uses the elite XP curve.

Load policy

  • Identifying User-Agent with a contact handle on every request.
  • One request at a time across the whole app. At least 5 seconds plus jitter between calls.
  • Hourly polls by default. Hiscores only change on logout or world hop, so polling more often adds load without adding data.
  • "Update now" is limited to once per 5 minutes per player and is served from the database while that window is open.
  • Retry only 429, 5xx and timeouts, honouring Retry-After. Back off exponentially up to 5 minutes. A circuit breaker pauses all polling after repeated failures.
  • A 404 marks the player not_found, and that player is retried once a day rather than every hour.
  • Player Events are fetched at most every 30 minutes, since the endpoint has a 10-minute cache.

Phases

  1. 1 · Research and blueprint

    API study, live probes, architecture, data model, planner math, load policy. Backfill script reviewed and hardened.

    ▲ Review gate. Stops here until you approve.

  2. 2 · Foundation

    Project scaffold, SQLite schema, a polite Index Lite client, XP tables with unit tests, a track add command, and import of the RuneMetrics CSV into monthly_rollups.

  3. 3 · Collector and gains

    Scheduled polling with dedupe, the gains queries (day, week, month, year, custom), daily rollups, and Player Events ingestion.

  4. 4 · Planner

    Per-skill targets, XP remaining, ETAs from your own rates or manual XP/hr, plus totals for "all 99", "all 120" and "all 200m".

  5. 5 · Dashboard

    Local web UI with a skill table, progress bars for each target, gains charts and an "Update now" button.

  6. 6 · Hardening

    Handling for name changes, multiple players, CSV export, and optional hosting.

Decisions for your review

Run the RuneMetrics backfill now

Recommended · deadline 10 Nov

This is the only source of past monthly gains. It takes about 3 minutes and 28 requests for one player. Skill 0 is already cached.

Stack

Python + SQLite + FastAPI

Standard library for the client. A static HTML and Chart.js front end served by the same process. One install, runs on Windows.

Where it runs

Local PC to start

Windows Task Scheduler or an in-process scheduler handles hourly polls. Hosting can come in phase 6.
